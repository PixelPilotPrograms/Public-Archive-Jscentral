Browser / Color

Turning HSL controls into a HEX color

The color mixer keeps hue, saturation, and lightness as the editable values. CSS can render that HSL value directly; the HEX readout is calculated separately so it can be copied into tools that expect RGB notation.

Conversion in three steps

Normalize saturation and lightness to 0–1. Chroma describes the distance from gray, and the hue selects one of six 60-degree RGB sectors. Add the lightness offset, round each channel to an 8-bit value, then pad each hexadecimal channel to two digits.

chroma = (1 - abs(2 * lightness - 1)) * saturation
sector = hue / 60
second = chroma * (1 - abs(sector % 2 - 1))

For a visual check, drag hue through the full 0–360 range, set saturation to 0 to confirm the result becomes gray, and set lightness to 0 or 100 to confirm black or white. Those boundary cases catch common conversion mistakes.

Browser / Motion

Restarting a CSS animation on demand

The oscilloscope experiment increments a pulse counter and retriggers a CSS keyframe animation on every click. Adding a class that is already present does not restart its animation, so the handler removes the class, reads the element's layout, and adds the class back.

The retrigger pattern

pulseLine.classList.remove('active');
void pulseLine.offsetWidth;
pulseLine.classList.add('active');

Reading offsetWidth forces the browser to resolve layout between the class changes. That gives CSS a distinct inactive state before the animation starts again. It is a small, targeted reflow; avoid putting repeated layout reads inside a large loop, where they can make rendering expensive.

The animation itself changes transform and opacity, which browsers can generally animate smoothly. The counter is updated as text, so it remains available to assistive technology instead of being drawn into the visual effect.

Browser / Timing

Modeling a reaction test as explicit states

The reaction timer has four states: ready, waiting, go, and result. A click starts a randomized delay; an early click cancels the timer, while a click after the signal measures elapsed time and updates the best result for the current page view.

Why use a monotonic clock?

performance.now() measures elapsed time relative to the page's time origin, so a system clock adjustment does not distort the result. The delay is 1,200–3,400 milliseconds; the measurement begins only when the signal appears.

reactionStart = performance.now();
const elapsed = Math.round(performance.now() - reactionStart);

This is a casual browser exercise, not a scientific measurement. Display refresh, input hardware, browser scheduling, and device load all affect the result. Keeping the state explicit makes early clicks and retries predictable, but a production test would also need accessible status announcements and more careful input handling.
